# 03 — Technical SEO audit: dadrose.com, book.dadrose.com / dadrosebook.com, azmoon.dadrose.com, Next.js rewrite

Date: 2026-10-13. Auditor: Claude (technical SEO sub-agent).

## 0. Method and limits (read first)

- Live pages were read with WebFetch (HTML converted to markdown by a summarising model). Consequence: **`<script>` contents (JSON-LD, gtag/GTM, verification tags inside scripts) and the `<html lang/dir>` attribute are stripped before I see them.** Everything reported as "no JSON-LD / no analytics" is therefore **unknown, not absent**. Verify with Google Rich Results Test / view-source.
- WebFetch obeys the `User-agent: *` group of each robots.txt. It refused **every** URL on `book.dadrose.com`, `azmoon.dadrose.com`, `dadrosebook.com` and `www.dadrose.com` with `ROBOTS_DISALLOWED` — including `/robots.txt` itself. That means either (a) robots.txt on those hosts disallows generic/AI agents, or (b) robots.txt could not be fetched from a non-Iranian IP (firewall / geo-block / 5xx, which crawlers treat as "disallow all" for 5xx). I could not tell which. web.archive.org is blocked from this environment; US-only WebSearch returned nothing for `site:` queries. **Those three hosts are therefore audited only from the outside (links into them) and from the local Next.js code.**
- Bash has no internet; HTTP status codes and redirect chains could not be observed directly. A WebFetch `SERVER_ERROR` on a URL is consistent with a 4xx/5xx, marked "inferred".
- PageSpeed Insights API (`runPagespeed?url=https://dadrose.com/&strategy=mobile`) returned CLIENT_ERROR (probably needs an API key / quota). **No CWV data collected.**
- Severity scale: critical / high / medium / low. "Inferred" = not directly observed.

### 1.2 robots.txt (verified, full content)
```
Sitemap: https://dadrose.com/sitemap.xml
User-agent: *
Disallow: /wp-admin/  /wp-includes/  /tag/  /cart/  /checkout/  /my-account/
Disallow: /*add-to-cart=*   */?s=*   /?s=*   */?*   *?*   */search?q=*   /search/
Disallow: /plms-lic/  /feed/  /trackback/  /rss/  /comments/feed/  /date/  /comments/
Disallow: *?preview_id=   *.htm   *.html   *.shtml   *.php
Allow: /wp-admin/admin-ajax.php   /wp-content/*.css   /wp-content/*.js
User-Agent: Mediapartners-Google / Adsbot-Google / Googlebot-Image / Googlebot-Mobile / Googlebot  -> Allow: /
```
(One directive per line in the real file; condensed here.)

**F1 — CRITICAL/HIGH: Googlebot group overrides every `*` rule.** Per RFC 9309 and Google's documentation a crawler obeys only the most specific matching group; `User-Agent: Googlebot` + `Allow: /` means Googlebot ignores all 25 disallows. Verified side effects:
- Google may crawl `/wp-admin/`, `/cart/`, `/checkout/`, `/my-account/`, `?add-to-cart=` (WooCommerce crawl trap — every product/course card emits one), `?s=` internal search (spam-search injection vector), `/feed/`, `/comments/`, `/date/` archives, `*?preview_id=`.
- Google will crawl and may index the course-archive facets: `/courses/?type=zero|summary|tips|golden|free`, `/courses/?subject=<10 subjects>`, `/courses/?pg=2..5` (all verified to exist on `/courses/`). That part is actually desirable for pagination, but uncontrolled for facets.
- Bing, Yandex, DuckDuckGo, and AI crawlers follow the `*` group: `disallow: *?*` blocks `/courses/?pg=2..5`, so **Bing cannot crawl course archive pages 2–5** and can reach those courses only via sitemap.
- `Googlebot-Mobile` is a retired token (harmless but noise); `Mediapartners-Google`/`Adsbot-Google` groups are irrelevant without AdSense/Ads.
- The two engines therefore see two different sites — the worst kind of robots configuration to debug.
**Fix:** delete all Google-specific groups (or copy the full disallow list into one combined group: `User-agent: *` plus `User-agent: Googlebot` lines stacked above the same rules). Replace the blanket `*?*` with targeted rules: keep `/*?s=`, `/*add-to-cart=`, `/*?preview`, `/*?replytocom=`, `/*?orderby=`; allow `?pg=`. Remove `*.php` (it also blocks `wp-login.php`-style URLs — fine — but is redundant) and `*.html` unless legacy .html URLs exist. Do not disallow `/feed/` if you want feeds as discovery for Bing (optional). Keep `/cart/ /checkout/ /my-account/` disallowed **and** noindex them (see F5).

## 2. Bookstore: book.dadrose.com vs dadrosebook.com

- The main site menu, footer and articles link to **`https://dadrosebook.com/`** («فروشگاه کتاب»), not `book.dadrose.com`. No link to `book.dadrose.com` was found on any dadrose.com page fetched.
- Both `book.dadrose.com` and `dadrosebook.com` (incl. `/robots.txt`) refused with ROBOTS_DISALLOWED. Nothing on-page could be audited. No inventory of book categories could be captured.

**F14 — CRITICAL (verify immediately): bookstore and exam hosts may be uncrawlable from outside Iran.** Same failure on `azmoon.dadrose.com`. Two explanations, both serious: (a) robots.txt contains `User-agent: * / Disallow: /` (or blocks all non-Google agents), or (b) the server firewall/geo-block (ArvanCloud/Iranian DC — the ADR says the new platform will also run on an Iranian server) returns 403/5xx to foreign IPs; Google treats an unreachable (5xx) robots.txt as "disallow all" after a grace period, and Googlebot crawls from US IPs. **Fix:** in Google Search Console add Domain property `dadrose.com` (covers all subdomains) and `dadrosebook.com`; run URL Inspection → "Test live URL" on each host's homepage and robots.txt; check Settings → Crawl stats → host status. Whitelist Googlebot/Bingbot IP ranges (Google publishes `googlebot.json`) in the firewall/CDN; make robots.txt return 200 to everyone.

**F15 — HIGH (inferred): Two domains for one bookstore.** If `book.dadrose.com` and `dadrosebook.com` both serve content, they duplicate each other; if one redirects, confirm it is a single 301 hop. Pick one canonical host (recommendation: keep `dadrosebook.com` if it has history/backlinks; otherwise consolidating to `book.dadrose.com` or `dadrose.com/books/` concentrates authority) and 301 the other at the path level.

Product page checks to run once accessible: Product schema (name, image, isbn, author, publisher, offers.price IRR, availability), unique descriptions vs publisher copy, category pages per subject, faceted `?filter_`/`?orderby=` noindex, out-of-stock handling.

### 5.2 Code-level recommendations (concrete)
1. **`frontend/src/app/robots.ts`** (new):
   ```ts
   import type { MetadataRoute } from "next";
   export default function robots(): MetadataRoute.Robots {
     return { rules: [{ userAgent: "*", allow: "/", disallow: ["/app/", "/api/", "/login", "/offline"] }],
              sitemap: "https://azmoon.dadrose.com/sitemap.xml", host: "https://azmoon.dadrose.com" };
   }
   ```
   One group only (do not repeat the dadrose.com Googlebot mistake).
2. **`frontend/src/app/sitemap.ts`** (new): emit `/`, `/guide`, and every new public route below; `lastModified` from content data (`src/content/exams.ts` / backend `updated_at`), not `new Date()`.
3. **Root metadata** (`src/app/layout.tsx`): add `metadataBase: new URL(process.env.NEXT_PUBLIC_SITE_URL ?? "https://azmoon.dadrose.com")`, `alternates: { canonical: "./" }` per page, `openGraph: { type: "website", locale: "fa_IR", siteName: "دادرز", images: ["/og.png"] }`, `twitter: { card: "summary_large_image" }`, `verification: { google: "…" }`. Change default title to distinguish from the main site, e.g. «آزمون آنلاین وکالت دادرز — شبیه‌ساز کانون و مرکز».
4. **noindex** `src/app/login/page.tsx` and `src/app/offline/page.tsx`: `robots: { index: false, follow: true }`.
5. **`src/app/not-found.tsx`** returning a real 404 with links to `/guide` and subject pages; for retired exams use `notFound()` or a 410 via route handler / `proxy.ts`.
6. **JSON-LD component** `src/components/seo/json-ld.tsx` (`<script type="application/ld+json" dangerouslySetInnerHTML>` — allowed by current CSP `'unsafe-inline'`; with a future nonce CSP pass the nonce). Use on: `/` → `Organization` (`@id https://dadrose.com/#organization`, sameAs socials) + `WebSite`; `/guide` and per-exam pages → `Article`/`WebPage` + `BreadcrumbList` + `Event` (exam date) if dates are verified; pricing → `Product`/`Offer` (IRR) or `Service`; subject pages → `Quiz`/`LearningResource` (`educationalLevel`, `about`, `teaches`) — Google's Practice Problems rich result requires `Quiz` markup for education content; sample questions → `Quiz` with `hasPart: Question`.
7. **New public SSR/SSG routes** (Server Components, `generateStaticParams`, `revalidate`):
   - `/guide/kanoon`, `/guide/markaz` — split the anchor sections of `/guide` (`#kanoon`, `#markaz` in `src/content/exams.ts`) into their own URLs targeting «آزمون وکالت کانون ۱۴۰۵» / «آزمون مرکز وکلا ۱۴۰۵».
   - `/subjects/[subject]` for the 10 keys in `backend/content/subjects.py` (civil, civil_procedure, commercial, usul_fiqh, fiqh_bar, criminal, criminal_procedure, constitutional, fiqh_center, registration_law): description, blueprint share (e.g. «حقوق مدنی: ۲۰ سؤال، ضریب ۳»), 5–10 free sample questions with explanations rendered in HTML, link to the dadrose.com course and the bookstore title for that subject, CTA to the full test.
   - `/subjects/[subject]/[topic]` once topic (مبحث) taxonomy is public.
   - `/past-exams/[year]/[track]` (سؤالات و پاسخ تشریحی آزمون وکالت ۱۴۰۴ …) if rights allow — highest-volume query family.
   - `/exam-dates` and `/score-calculator` (calculator exists on dadrose.com — avoid duplication; link instead).
   - Public, shareable **sample report card** page (`/sample-report`) — static demo, noindex user reports.
   Needed backend: an anonymous read-only endpoint (e.g. `GET /api/v1/public/subjects`, `/public/sample-questions?subject=`) — currently all `backend/exams/urls.py` / `content/urls.py` views are for the app; `content/urls.py` has `subjects` only.
8. **Header/footer** (`src/components/public/site-header.tsx`): add links to `https://dadrose.com/courses/`, `https://dadrose.com/blog/`, `https://dadrosebook.com/` and per-subject pages; add breadcrumb component for public routes.
9. **Analytics**: add first-party measurement compatible with the CSP — either GA4 via server-side Measurement Protocol from the BFF, or self-hosted Matomo/Umami on the same origin path (`/stats`), or extend CSP `script-src`/`connect-src` to `https://www.googletagmanager.com https://*.google-analytics.com` (contradicts ADR; owner decision). GSC verification via `metadata.verification.google` or DNS TXT (preferred, covers all subdomains).
10. **Migration 301s**: in `next.config.ts` `redirects()` map legacy WordPress azmoon URLs → new routes; on dadrose.com, 301 `/azmoon/` → `https://azmoon.dadrose.com/` once the new app is live.
11. **Hosting**: since ADR-0002 puts the stack on an Iranian server, ensure foreign crawler IPs are not geo-blocked (F14).
